# 付録 B. 起動スタックの読み方

Step 3 §「カーネルから動的リンカへの情報の渡し方: スタック」に出てくる
スタック図 (argc / argv / envp / auxv が積まれた絵) を読むには、

- スタックがどちらに伸びるか
- `RSP` がどこを指すか
- `argc` / `argv` / `envp` の C 規約
- ポインタ配列と文字列本体が別の場所にあること
- `auxv` とは何か

の前提知識が要る。本付録はそれを `./main` という極小の例で順に組み立てる。

---

## スタックは下 (低アドレス) に伸びる

x86-64 では、スタックは **高アドレスから低アドレスに向かって** 育つ。
新しい値を `push` すると番地が減る:

```
   高アドレス
       +------+
       | A    |   <-- 最初に push したもの
       +------+
       | B    |   <-- 次に push したもの
       +------+
       | C    |   <-- 最後に push したもの (= 現在の先頭)
       +------+
   低アドレス
```

図では「先に積まれたもの」が上、「あとから積まれたもの」が下にくる。

---

## RSP — スタックの現在地

CPU レジスタ `RSP` (Stack Pointer) は **現在のスタック先頭 = 最後に
積まれた値のアドレス** を指す。新しく push すれば `RSP` が減り、
pop すれば `RSP` が増える。

上の図でいう `C` (最後に push したもの) が現在の `RSP` の指す先。
プログラムがスタックに最初にアクセスする入口でもある。

---

## argc / argv / envp — C プログラムへの起動引数

C で書かれたプログラムの `main` は

```c
int main(int argc, char **argv, char **envp);
```

という形で起動引数を受け取る:

- `argc` — コマンドライン引数の個数 (プログラム名自身を含む)
- `argv` — 引数文字列へのポインタ配列、`argv[argc] = NULL` で終端
- `envp` — 環境変数文字列 (`"PATH=..."` 形式) へのポインタ配列、
  末尾は `NULL` で終端

これらの値はカーネルが `execve` 時にスタック上に並べる。
プログラムが自分で push したわけではない。

---

## `./main` 実行時のスタック全体像

引数ナシで `./main` を起動した時にカーネルが用意するスタック
(環境変数も `PATH=/usr/bin` の 1 個だけと仮定):

```
   高アドレス
       +-----------------------------+
       | (文字列の実体: ./main\0,    |
       |  PATH=...\0 など)            |
       +-----------------------------+
       | auxv: AT_NULL, 0            |
       | auxv: ... 中身 ...           |  <-- ELF 情報を ld-linux.so に渡す
       | auxv: AT_PHDR, ...          |
       +-----------------------------+
       | envp[1] = NULL              |
       | envp[0] = (PATH... の番地)  |
       +-----------------------------+
       | argv[1] = NULL              |
       | argv[0] = (./main の番地)   |
       +-----------------------------+
       | argc                        |  <-- RSP
       +-----------------------------+
   低アドレス
```

構造の要点:

- 一番上 (高アドレス側) に **文字列の実体** が置かれる。固定サイズの
  配列ではなく、`\0` 終端の C 文字列が連続して並ぶ。
- その下に **ポインタ配列** — auxv、envp[]、argv[] の 3 ブロック。
  各要素は 8 バイト (auxv だけ 16 バイト: キー 8 + 値 8)、上の文字列
  実体を指す番地か `NULL`。
- 一番下 (低アドレス側 = `RSP` の指す位置) に `argc`。

つまり「ポインタ配列」と「文字列の実体」は別の場所にある、**二段構成**。
`argv[0]` は文字列そのものではなく、文字列が置かれた番地。

### auxv の役割

envp[] の上に積まれている `Auxiliary Vector` (auxv) は、
**ELF をロードする側 (= `ld-linux.so`) にだけ必要な情報を渡す専用
チャンネル**:

- どこに `main` の Program header があるか (`AT_PHDR`)
- `main` の `e_entry` はどこか (`AT_ENTRY`)
- `ld-linux.so` 自身の `base` はどこか (`AT_BASE`)

など、`./main` を起動した時点でカーネルしか知らない値を、auxv 経由で
`ld-linux.so` に伝える。auxv は `(キー, 値)` のペアの配列で、
`AT_NULL = 0` のキーで終端する。

auxv に入るキーのうち本シリーズで使う 5 つの意味は
Step 3 § Auxiliary Vector (auxv) の中身 を参照。

## Step 3 のスタック図に戻る

Step 3 のスタック図を再掲する:

```
   高アドレス
       +------------------------------+
       | (env 文字列 の実体)            |   "PATH=/usr/bin\0"  など
       | (arg 文字列 の実体)            |   "./main\0"
       +------------------------------+
       | Auxiliary Vector (auxv)      |
       |   AT_NULL,  0                |
       |   ...                        |
       |   AT_ENTRY, base_main+0x1050 |   (= 実 VA、PIE のため base 加算)
       |   AT_BASE,  base_ld          |
       |   AT_PHNUM, 13               |
       |   AT_PHENT, 56               |
       |   AT_PHDR,  &main_phdr       |
       +------------------------------+
       | envp[N] = NULL               |
       | envp[N-1] = "PATH=..."       |
       | ...                          |
       | envp[0]                      |
       +------------------------------+
       | argv[argc] = NULL            |
       | argv[argc-1]                 |
       | ...                          |
       | argv[0] = "./main"           |
       +------------------------------+
       | argc                         |   <-- RSP はここを指している
       +------------------------------+
   低アドレス
```

対応:

- 一番上の「env 文字列の実体 / arg 文字列の実体」 = 本付録の「文字列の
  実体」段
- `Auxiliary Vector (auxv)` = 本付録の auxv 段
- `envp[]` / `argv[]` = 本付録のポインタ配列段 (末尾 `NULL` 終端)
- `argc` = `RSP` の指す位置 = ld-linux.so が起動した瞬間に最初に見る値

実引数を伴う例 (例: `./main foo bar` → `argc = 3`, `argv[0..3]` で
末尾 `NULL`) でも、形は同じで「ポインタ配列の長さと文字列の本体が
増える」だけ。
